# M3 平铺树状任务界面需求

- 功能 ID：`m3-task-ui`
- 需求状态：已确认，可进入独立规划
- 确认日期：2026-07-31

## 1. 背景与目标

NGAPD 已完成 M0“领域基线和工程骨架”、M1“项目、角色和成员”以及 M2“任务管理闭环”。M2 已提供正式 Schema version 3、完整 Task `/api/v1`/OpenAPI、递归任务树、同级 DAG、显式/有效 Owner、权限与管理员模式、状态与生命周期、影响预览、评论、活动、站内通知、审计、Outbox、Worker、SSE 和任务级逻辑 Workspace 服务端状态，但刻意没有实现正式 Task Web 界面。

前置 Task UI 原型已经在 macOS Chromium 和 Windows Chrome 上验证“一个当前父级作用域的一幅 DAG + 选中任务的右侧非模态详情抽屉 + 直接子任务列表 + 专用下降按钮 + 面包屑/返回上级 + 搜索/筛选”的交互，在单层 200 个任务时满足既定可用性和性能门槛。该原型使用内存夹具，属于交互证据，不是生产数据、权限或接口权威。

M3 的目标是在现有已认证 React Web 和项目上下文中交付正式平铺树状任务界面。活动项目成员必须能够从虚拟项目根浏览到任意深层 Task Key，理解当前层的同级依赖和任务详情，并通过服务端当前 `actions` 完成 M2 已提供的全部人类操作，而无需借助 Swagger 或直接构造 API 请求。Project Owner 和 Project Admin 的跨 Owner 操作继续要求显式、有效的项目管理员模式；任何客户端状态或可见按钮都不得成为授权权威。

可观察结果包括：

1. 用户可以稳定浏览、搜索、筛选、深链和恢复任意活动任务，且不会混淆父子层级与 predecessor → successor 依赖方向。
2. 用户可以在同一正式界面安全执行 M2 全部人类任务管理流程，包括创建、字段编辑、Owner、依赖及请求、关注、blocker、状态、完成/重开、移动、归档、不可恢复删除、评论、活动和通知。
3. 并发、版本漂移、管理员模式过期、权限变化、SSE 失效和网络错误不会产生静默覆盖、重复业务结果、错误确认或跨项目数据泄露。
4. M3 不提前实现 M4 本地 Workspace 同步写入、M5 Agent 工具或 M6 摘要/Wiki；这些后续里程碑可以继续复用 M2 权威事实和 M3 的正式 Web 集成边界。

## 2. 范围

### 2.1 包含范围

- 在现有 `apps/web` 已认证应用和项目上下文中增加正式 Task 页面，同时保留账号、资料、项目、成员、角色、所有权、Admin Mode、设备与 Workspace 页面。
- 虚拟项目根下的顶层任务 DAG，以及任意普通任务作为当前父级作用域时的直接子任务 DAG。
- 当前层全部可见任务、孤立节点、同级 predecessor → successor 依赖、图版本和被筛选/分页隐藏关系的明确提示。
- 选中节点后打开右侧非模态详情抽屉；抽屉显示完整任务详情、直接子任务摘要、评论、活动、Workspace 状态和服务端允许的操作。
- 只有抽屉内明确的“进入子任务视图”操作可以下降层级；直接子任务列表行不得成为隐式的第二种下降语义。
- 面包屑、返回上一级、每层视口与筛选恢复、项目/Task 正式深链、刷新恢复和浏览器前进/后退。
- 项目级 Task Key/标题搜索、祖先链定位、返回搜索前位置，以及当前层按有效 Owner、逻辑角色、有效状态、截止时间和标签的 AND 筛选。
- 活动 DAG 与归档历史分离；已归档顶层任务及其历史子树可以在明确的历史视图或深链中只读查看，不参与活动依赖、状态或完成计算。
- 普通、冲刺、里程碑的差异化非纯色外观；中文、键盘、焦点、屏幕阅读器可辨关系和颜色之外的状态表达。
- M2 全部面向人类 Session 的 Task 写入界面：创建顶层/子任务、字段编辑、Owner 变化、依赖增删/请求/接受/拒绝、关注、blocker、基础状态、完成、重开、移动、归档和不可恢复删除。
- M2 评论、活动和站内通知界面，包括本人评论编辑/删除、管理员隐藏、分页、通知已读状态和允许配置的通知偏好。
- 从当前用户有权读取的服务端 Task Workspace 当前版本中选择既有文件作为评论附件，并安全打开仍存在且仍有权读取的附件；不新增 Workspace 文件写入能力。
- 使用 M1 项目成员、逻辑角色和 Admin Mode 数据把 Task 中的稳定 ID 显示为可理解名称与状态，同时保留不可变历史引用。
- TanStack Query 缓存、稳定 query key、每次用户意图一个幂等键、SSE 资源失效后重新获取，以及写入成功/失败后的精确缓存失效。
- 为正式搜索、祖先链定位、结构化过滤和人类 Session 下的 Task Workspace 附件读取补齐必要的共享运行时契约、Repository 查询和 `/api/v1`/OpenAPI 只读能力。
- 200 同层任务、项目 5,000 活动任务和深度 20 的正确性与目标性能验证，以及适用的 Web/API/PostgreSQL/发布回归。

### 2.2 不包含范围

- 不实现语义缩放、无限画布、递归嵌套图、节点内子图、第二幅同时可见的 DAG、自动排期、甘特图或复杂拖拽动画。
- 不允许通过拖动节点或边、客户端图布局或本地缓存直接改变父子、依赖、Owner、状态或其他服务端事实；所有写入继续走 M2 应用服务、权限、版本、影响和审计边界。
- 不实现 M4 的 macOS/Windows 本地目录物化、文件监听、上传、下载队列、租约获取/接管、冲突选择或 Workspace 写入 GUI。
- 不实现 M5 的 Agent 工具、Skill、`propose -> confirm -> execute` 协议、Agent actor 公共入口或 Agent 管理员模式。
- 不实现 M6 的完成摘要、KnowledgeEntry、Wiki、任务正文全文搜索、摘要版本、外部模型调用、项目备份或恢复界面。M3 只提供 Task Key/标题定位。
- 不实现邮件、Slack、Teams 或其他外部通知渠道；M3 只呈现 M2 站内通知。
- 不改变 M2 的任务字段、状态机、Owner 继承、依赖权限、完成冻结、重开策略、影响集合、Workspace 原子性、审计或租户隔离语义。
- 不新增自定义字段、自定义任务类型、自定义状态机、预计工时、任务回收站、单任务恢复、项目永久删除或跨父级依赖。
- 不把归档历史节点混入活动 DAG，不提供已归档任务恢复，也不允许从历史视图发起任务管理写入。
- 不把移动端原生应用、触摸优先交互或低于 1280×720 的完整布局作为 core；较窄桌面视口只要求不泄露数据、不误提交和提供明确降级。
- 不建立独立前端微应用、SSR 应用、Redis、独立搜索服务、外部分析服务或外部 AI/LLM 依赖。

## 3. 已确认的项目事实与约束

- [总体实施路线](../../07-roadmap-and-validation.md)把 M3 定义为 M2 服务端闭环之后的正式平铺树状 Task UI，并要求虚拟根、当前层、详情、子任务、面包屑、返回、展示类型、搜索、过滤和 200 节点验证。
- [产品需求](../../01-product-requirements.md)、[领域模型](../../02-domain-model.md)、[权限模型](../../03-permission-model.md)、[系统架构](../../04-system-architecture.md)和[MVP 非功能基线](../../10-mvp-non-functional-baseline.md)已经固定任务树、同级 DAG、虚拟根、Owner、状态、依赖方向、权限、时区、界面范围和性能门槛。
- [M2 当前有效需求](../m2-task-management/effective-requirements.md)是 Task/Graph/Owner/Workspace/评论/活动/通知/API 的当前生产权威；M2 initial 记录已经冻结，M3 不得改写其 requirements、result、`change-0.md` 或 effective snapshot。
- 当前正式数据库 profile 为 version 3，最新迁移为 `0009-m2-task-management`。M3 预期以查询和 Web 集成为主；若目标性能需要新增索引或查询投影，只允许非破坏性、可重复、可诊断的向前迁移，不得 reset 或重写现有事实。
- M2 的 Task 列表响应已经包含完整 Task 资源、当前父级图版本和同级依赖，支持 `parentTaskKey`、生命周期、稳定 Task Key 游标和每页最多 200 项；当前没有正式的项目级 Task Key/标题搜索、祖先链定位或 Owner/角色/状态/截止时间/标签查询参数。
- M2 所有 Task 响应携带服务端计算的 `actions`。每次写入仍重新解析当前 Session、项目、活动 Membership、有效 Owner、Admin Mode、Task/Graph/Workspace 版本和影响集合，客户端不得依据旧按钮状态假定授权。
- M2 已提供创建/更新、Owner 影响与提交、依赖及变更请求、关注影响与提交、blocker、状态、完成/重开、移动、归档/删除影响与提交、评论、活动、通知、通知偏好和 Task Workspace 状态接口。
- Workspace 元数据、版本清单和对象读取目前使用设备 Bearer 凭据；正式 Web 使用 SameSite Session。M3 若要安全选择或打开评论附件，必须提供 Task 作用域、Session 授权、只读且不暴露设备/租约秘密的适配入口。
- M1 Web 使用 React 19、Vite、TypeScript、TanStack Query、同源 API/error 层、稳定 query key、幂等用户意图和项目级内存 Admin Mode ID；当前没有正式路由器，项目和页面选择主要保存在 React 内存中。
- 现有 SSE 只提供精确 user/project audience 的 `resource-invalidated` 提示，客户端必须 refetch 权威资源；实时事件不是第二业务事实，也不得直接当作写入成功。
- 封存 Task UI 原型已经验证单 DAG、非模态抽屉、专用下降、搜索/筛选、深层恢复、键盘、非颜色表达和 200 节点性能；其确定性夹具、原型入口和截图只能作为回归证据，不能替代正式 API 或服务端授权。
- 用户明确选择 M3 覆盖 M2 全部人类操作，并明确选择沿用原型的单 DAG/详情抽屉/专用下降交互。
- 用户接受正式深链与浏览器历史默认：刷新、后退和前进可以恢复项目、当前父级作用域和选中 Task；现有 `/` 行为与精确 `?prototype=task-ui` 入口继续兼容。
- 用户接受归档默认：活动 DAG 与归档历史明确分离，归档任务只读且不参与活动计算。
- 任务正文、评论、角色文本、标签、文件名和 Workspace 内容均是不可信输入；显示 Markdown 或附件时不得执行内嵌脚本、任意 HTML、危险 URL 或工作区外路径。
- 服务端运行时不得调用外部 API、AI 或 LLM，也不得向外部服务发送项目、任务、评论、通知或 Workspace 内容。
- Agent 流程文档根为 `docs/requirements`；本功能使用独立 `m3-task-ui` 目录和 schema `3.2` 合同。
- 需求确认时项目分支为 `codex/m3-task-ui`，基线提交为 `9f0a8398c63582f21ed26451bb727f9daca0d89c`，工作区无既有差异。

## 4. 交付与验证策略

- 用户在 2026-07-31 明确选择本次 initial run 使用 `relaxed`。
- `relaxed` 允许实现先于测试，不要求人为制造 red-first 证据。
- 所有 `core` 验收、功能正确性、授权、隐私、租户隔离、数据完整性、危险操作确认、乐观并发、公共兼容性、构建能力、恢复安全和项目/发布硬门禁继续阻塞。
- 只有独立证明确实不影响已交付行为的 `supplemental` 异常，才可按严重程度登记为 `FND-I-*` report-only finding；`critical`/`high`、安全/隐私/数据/兼容性、构建/运行时、未知影响或 core 异常不得留作 report-only。
- 不得在失败后把验收从 `core` 降为 `supplemental`。产品影响不确定时按 `core` 处理。
- 验证必须与完整 M2 人类操作界面的风险相称，至少覆盖共享契约/OpenAPI、查询与权限、真实 PostgreSQL 写入/并发、Web 交互、SSE 失效、可访问性、200 节点浏览器性能、现有 M1/prototype 兼容和适用的根工程/发布门禁。

## 5. 功能需求

- `FR-001`：正式 Task UI 必须位于现有已认证 Web 和当前项目上下文中；非登录用户、非活动 Membership 或无项目读取权用户不得看到项目 Task 数据。现有认证、资料、项目治理、成员、角色、Admin Mode、设备与 Workspace 页面不得回归。
- `FR-002`：任一时刻必须只有一个当前父级作用域和一幅活动 DAG。作用域为虚拟项目根时节点必须是活动顶层 Task；作用域为普通 Task 时节点必须恰好是该 Task 的活动直接子 Task。
- `FR-003`：当前 DAG 必须呈现全部已加载且符合筛选的同级节点，包括没有依赖边的孤立节点；每条边必须明确表达 predecessor → successor，不得绘制跨父级边、自环、反向边或把父子关系画成依赖。
- `FR-004`：DAG 必须使用尺寸有限、可滚动且可裁剪/虚拟化的视口。过滤或分页使依赖端点不可见时，只能显示两端都可见的边，并必须提示仍存在被隐藏的同级关系；不得为了性能静默丢弃权威节点或边。
- `FR-005`：打开项目根、进入任一新层或通过返回上级恢复层级时，默认不得自动选择任务，详情抽屉必须收起。用户选择 DAG 节点后，系统必须保持当前父级作用域和 DAG 布局，从右侧打开非模态详情抽屉。
- `FR-006`：详情抽屉必须展示 Task Key、标题、安全呈现的 Markdown 正文、显式 Owner、有效 Owner、继承来源、逻辑角色、基础/有效状态、完成就绪、设备本地时区截止时间、标签、展示类型、直接子任务统计、Task/Graph 版本、Workspace 生命周期/工作周期/同步版本和当前 `actions` 对应的人类操作。
- `FR-007`：选择同层另一节点必须原位替换抽屉内容，不得改变父级作用域或重排当前 DAG。点击明确收回按钮或按 `Escape` 必须清除选择和高亮、收起抽屉，并把焦点返回原 DAG 节点，同时保留层级、筛选、搜索和视口。
- `FR-008`：详情抽屉必须以独立列表展示选中 Task 的直接子任务摘要。列表不得渲染第二幅 DAG，点击列表行不得下降层级；只有明确的“进入子任务视图”操作可以把选中 Task 设为新的父级作用域。
- `FR-009`：执行“进入子任务视图”后，DAG 必须整体替换为该 Task 的直接子任务和同级依赖，抽屉收起、选择清空且不自动选择首个子 Task。无直接子任务时该操作必须禁用并说明原因。
- `FR-010`：面包屑必须表达从虚拟项目根到当前父级作用域的完整祖先链；返回上一级或选择祖先面包屑必须恢复目标层已保存的筛选、视口和滚动位置，同时保持无选择和抽屉收起。
- `FR-011`：正式 URL 必须能够表达当前项目、当前父级作用域和可选的选中 Task。有效深链刷新后必须恢复相同可观察位置；浏览器后退/前进必须重放导航与选择，而不得重放写入或重复确认。具体 URL 结构不得破坏现有 `/` 和精确 prototype 入口。
- `FR-012`：系统必须提供项目级 Task Key 精确/前缀和标题不区分大小写包含搜索。搜索结果必须返回足以验证项目、活动/归档状态和完整祖先链的服务端事实；选择结果必须打开目标所在父级 DAG、选中目标并打开详情抽屉，不得通过下载全部项目正文到浏览器实现搜索。
- `FR-013`：搜索跳转前必须保存当前页面位置；“返回搜索前位置”必须恢复原项目、父级作用域、筛选、视口、滚动、选择和抽屉状态。无结果、陈旧结果、已删除目标或无权目标必须提供明确且不泄露跨项目信息的恢复路径。
- `FR-014`：有效 Owner、任务逻辑角色、有效状态、截止时间和标签筛选必须作用于当前层并按 AND 组合。筛选隐藏选中节点时必须清除选择并收起抽屉；清除筛选必须恢复当前层完整可访问节点。
- `FR-015`：普通、冲刺和里程碑必须使用图标、文字、边框或等价的非纯色差异外观，并复用完全相同的选择、详情、导航、搜索、筛选、依赖和权限语义。
- `FR-016`：活动视图不得混入归档顶层任务或其历史子树。项目根必须提供明确的归档历史入口；历史视图和归档深链只能读取保留的 Task/依赖/评论/活动事实，不得把历史边当作活动约束或显示写入操作。
- `FR-017`：当前层必须支持稳定分页或等价增量加载并保持 Task Key 顺序。单层 200 个 Task 必须能够完整交互；超过 200 时全部有权节点仍必须可通过分页、搜索或筛选访问，且不得把 200 写成产品硬限制。
- `FR-018`：活动成员必须能够在虚拟项目根创建顶层 Task，并在有权管理的 Task 下创建子 Task。顶层创建必须选择活动显式 Owner；子 Task 可以选择活动显式 Owner或明确继承。每次创建意图必须使用稳定幂等键并显示服务端分配的不可复用 Task Key。
- `FR-019`：详情抽屉必须按当前 `actions` 允许编辑未完成 Task 的标题、Markdown 正文、可选逻辑角色、UTC 截止时间、标签和 `normal / sprint / milestone` 展示类型。表单必须使用当前 Task 版本，服务端拒绝时不得把草稿显示为已提交事实。
- `FR-020`：Owner 变化必须先获取并展示服务端完整影响，包括后代有效 Owner、Task/Workspace 版本、活动租约和未提交 Workspace 状态；只有用户明确确认同一影响集合后才能提交。界面不得把未知的本地未提交状态默认为“无”，也不得替用户选择本地或服务端版本；无法证明安全前态时必须阻止提交并要求先完成 M4 所属的同步/冲突处理。顶层不得清空 Owner，非顶层清空必须明确展示将回落到的祖先 Owner。
- `FR-021`：当前层必须允许按明确的 predecessor → successor 方向添加或移除依赖，并展示当前 `graph_version`。服务端返回直接执行时刷新 DAG；返回 `request_required` 时必须明确显示待另一端 Owner 处理，不能把请求显示为已生效边。
- `FR-022`：项目 Task UI 必须提供依赖变更请求列表，并允许当前有权接受者接受或拒绝。过期、Owner 变化或图版本漂移导致的 `expired/stale` 请求必须显示稳定状态和重新发起建议，不得自动重放旧确认。
- `FR-023`：有效 Owner或有效 Admin Mode 必须能够从有权 Task 添加/移除同项目一跳关注；操作必须先展示服务端影响并明确关注不授予写权限、不参与状态/依赖/完成且不递归。
- `FR-024`：有效 Owner或有效 Admin Mode 必须能够为未完成 Task 添加带原因的人工 blocker，并解决仍活动的 blocker。界面必须同时区分人工 blocker、未完成 predecessor 导致的派生 blocked 和保留的基础状态。
- `FR-025`：界面必须允许执行服务端 `actions` 授权的 `not_started / in_progress` 基础状态变化和显式完成。完成必须展示直接子任务、predecessor、blocker、Task/Graph/Workspace 版本、活动租约及 `completion_ready` 事实，并要求用户明确确认已收到最终服务端版本以及是否存在本地未提交版本；界面不得把这两个输入静默预填为安全值。条件、租约、未提交状态或版本漂移时必须拒绝并重新读取，绝不得由 UI 自动完成父 Task或替用户处理 Workspace 冲突。
- `FR-026`：已完成 Task 必须以冻结状态呈现，只保留评论、显式重开和顶层归档等服务端允许操作。重开必须遵守项目 `deny/cascade` 策略；级联时先展示完整 successor 闭包、Owner、版本和 Workspace 工作周期影响，跨 Owner 必须要求有效 Admin Mode。
- `FR-027`：移动 Task 必须先请求服务端影响预览，并明确展示源/目标父级、受影响依赖、后代、Owner、完成祖先和两个图版本。只有确认令牌和版本仍有效时才提交；界面不得以拖放视觉结果替代服务端提交。
- `FR-028`：顶层归档和非顶层不可恢复删除必须先展示服务端完整影响。删除必须要求操作者输入待删子树根的完整 Task Key并完全匹配；归档不得被描述为可恢复，删除不得提供回收站或撤销。成功后深链和缓存必须转入明确的历史/已删除结果，不能残留可编辑幽灵节点。
- `FR-029`：活动成员必须能够发布 Markdown 评论并选择当前有权读取的既有 Workspace 文件引用作为附件。未完成 Task 中，作者只能按服务端 `actions` 编辑或删除本人评论；完成后评论追加式不可变；有效 Admin Mode 只能按要求提供原因后隐藏并保留审计事实。
- `FR-030`：M3 必须为人类 Session 提供 Task 作用域、只读、租户过滤的 Workspace 当前清单和附件内容访问，不得暴露设备 access token、lease token、连接 ID、对象存储路径或 Workspace 写入口。附件在提交前和打开时都必须重新校验 Task/Workspace 读取权、路径与可选哈希。
- `FR-031`：详情抽屉必须提供可分页的 Task 活动流，按服务端游标稳定续读并用成员/资源引用呈现业务友好事件。活动流不得允许修改历史，也不得代替不可变审计或 Task 权威事实。
- `FR-032`：已认证用户必须能够查看跨项目站内通知、未读/关键状态、标记已读/未读，并从仍有效的通知安全导航到对应项目和 Task。可配置通知偏好必须尊重服务端 `configurable`；关键通知不得被关闭。已删除或无权目标必须保留通知语义而不泄露资源内容。
- `FR-033`：Task UI 必须持续展示当前项目 Admin Mode 是否有效，并仅依据服务端 `actions` 显示或启用写操作。需要管理员能力时必须引导用户显式进入现有项目 Admin Mode；不得自动进入、跨项目复用或在过期后继续携带旧能力。
- `FR-034`：每个用户写入意图必须绑定适用的 Task/Graph/Workspace/评论/通知版本、影响令牌和幂等键。网络重试只能复用同一负载的幂等键；成功、用户修改负载或开始新意图后必须使用新键。`stale/conflict` 必须保留可恢复草稿、重新获取权威事实并要求重新确认，不得静默覆盖。
- `FR-035`：Task、图、评论、活动、通知、成员、角色、项目或 Admin Mode 的 SSE 失效必须使相关 query key 重新获取。失效到达时不得覆盖正在编辑的本地草稿或自动重新提交；若权威版本变化，必须标出冲突并使旧影响确认失效。
- `FR-036`：所有 Task、评论、角色、标签、活动引用和 Workspace 文件名必须按不可信输入呈现。Markdown 必须禁用或清理脚本、危险 HTML/URL；附件路径必须规范化且限定在已授权清单；错误、日志、URL、SSE 和界面不得泄露密码、Cookie、token、lease secret、完整敏感正文或跨项目标识。
- `FR-037`：M3 的完成界面必须明确说明当前 M2 完成会冻结 Task/Workspace，但摘要和 Wiki 属于 M6。M3 不得伪造摘要、调用模型或把缺少摘要显示为完成事务失败；M6 之后可以在不改变 M3 任务权限和导航不变量的前提下扩展该流程。
- `FR-038`：新增的搜索、祖先链、筛选或附件读取能力必须位于 `/api/v1`、使用 TypeBox 运行时 Schema并进入 OpenAPI 3.1，复用 Session、项目成员和 Task 授权，不得改变现有 M2 路径的成功/错误语义或开放客户端自称 actor/admin/project 的旁路。
- `FR-039`：M3 不得引入第二份 Task、图、评论、通知或权限持久化事实。URL 和客户端缓存只保存导航/交互状态；写入成功以后服务端响应和重新获取结果是唯一权威。若需要新增索引或查询投影，必须可由现有 Task 事实重建并保持已有 ID、Key、版本、历史和审计不变。
- `FR-040`：现有精确 `?prototype=task-ui` 夹具入口必须继续隔离、确定且不访问生产 Task API；正式 M3 页面不得导入原型夹具作为运行时业务数据。可复用的纯布局或交互代码必须改为消费正式契约并保持原型回归可执行。

## 6. 用户流程或调用流程

### 6.1 打开项目和浏览层级

1. 已认证活动成员打开一个有权项目并进入正式 Task 页面。
2. 系统从虚拟项目根读取活动顶层 Task、当前图版本和顶层依赖，初始无选择且抽屉收起。
3. 用户选择节点，右侧抽屉显示权威详情和当前 `actions`；选择另一节点只替换抽屉内容。
4. 用户通过抽屉内专用操作进入该 Task 的子任务视图，再使用返回上一级或面包屑恢复祖先层。
5. 每次层级切换更新正式 URL；刷新、后退和前进恢复导航状态但不重复写入。

### 6.2 搜索、筛选和历史

1. 用户按 Task Key 或标题发起项目级搜索；服务端返回匹配项、活动/归档状态和祖先链。
2. 用户选择活动结果后，系统打开目标父级 DAG、选中目标并打开抽屉。
3. 用户可以返回搜索前完整位置，或在当前层组合 Owner、角色、状态、截止时间和标签筛选。
4. 用户从项目根显式进入归档历史或打开归档深链时，界面切换为只读历史状态，不把历史节点/边混入活动 DAG。

### 6.3 创建和编辑普通 Task

1. 用户在项目根或当前有权父 Task 发起创建，填写标题、正文、角色、UTC 截止时间、标签、展示类型和适用 Owner。
2. 系统依据顶层/子任务规则校验 Owner，并用一次用户意图的幂等键提交。
3. 成功后系统以服务端 Task Key 和版本刷新当前层；失败时保留输入并显示稳定恢复建议。
4. 用户编辑现有 Task 时携带当前版本；并发漂移后重新读取并由用户决定如何调整草稿，不自动覆盖。

### 6.4 责任、依赖、关注和 blocker

1. Owner 变化、关注、移动或其他影响操作先读取服务端影响并展示给用户。
2. 依赖操作明确选择 predecessor 和 successor；服务端决定直接生效还是创建另一端 Owner 需要处理的请求。
3. 依赖请求接受者在项目请求列表中接受或拒绝；过期/stale 请求只能重新发起。
4. 用户可以添加/解决人工 blocker，并清楚看到人工阻塞、依赖阻塞和基础状态之间的区别。

### 6.5 状态、完成、重开和存续操作

1. 用户按服务端 `actions` 改变基础状态；父任务满足条件时只显示“可完成”，不自动完成。
2. 完成前界面展示子任务、依赖、blocker、Workspace/版本/租约条件，要求用户明确确认最终服务端版本与本地未提交状态，并说明摘要/Wiki 留待 M6。
3. 重开按 `deny/cascade` 展示结果；级联跨 Owner 时必须先显式进入 Admin Mode并确认完整闭包。
4. 移动、归档和删除均先展示影响；删除还要求完整 Task Key。成功后重新获取当前层、祖先、搜索和深链状态。

### 6.6 评论、附件和活动

1. 用户在详情抽屉查看分页评论和活动。
2. 发布评论时可以从当前 Task Workspace 的授权清单选择既有文件；M3 不上传或修改 Workspace 文件。
3. 评论编辑、删除或隐藏按钮完全由评论 `actions` 和 Task 状态决定；隐藏必须填写原因。
4. 附件打开时重新授权；文件缺失、哈希变化或权限撤销时给出稳定错误，不尝试绕过。

### 6.7 通知与管理员模式

1. 用户从全局站内通知入口查看分页通知和未读状态，并导航到仍可访问的项目/Task。
2. 用户可以更改非关键通知偏好；关键偏好保持不可关闭。
3. 普通操作需要管理员能力时，界面解释原因并引导用户显式进入对应项目 Admin Mode。
4. Admin Mode 过期、退出或项目切换后，Task 操作立即重新获取 `actions`，旧管理员确认不可继续使用。

### 6.8 并发、实时失效和恢复

1. 写入期间系统显示待提交状态，不把客户端草稿或乐观结果当作已提交事实。
2. 成功响应使相关 Task、图、评论、活动、通知和项目 query 精确失效并重新获取。
3. SSE 或提交响应发现版本漂移时，界面保留草稿、展示权威变化并要求重新预览/确认。
4. 网络中断后，同一未改变意图可以使用原幂等键重试；是否成功未知时先查询权威事实，不创建第二个业务结果。

## 7. 数据、接口与状态

### 7.1 服务端权威数据

M3 必须直接消费或兼容扩展以下现有权威资源：

- Project、当前 Membership、项目成员、逻辑角色和 Admin Mode。
- Task 完整资源、服务端 `actions`、显式/有效 Owner、基础/有效状态、直接子任务统计、Graph/Task/Workspace 版本。
- 当前父级的同级依赖和 `graph_version`。
- Owner/移动/归档/删除/关注/级联重开的影响集合与确认令牌。
- 依赖变更请求及其状态。
- blocker、评论、活动、通知和通知偏好。
- Task Workspace 生命周期、工作周期、同步版本，以及经 Task Session 授权暴露的当前只读文件清单/附件内容。

客户端不得重新计算有效 Owner、权限、完成资格、影响集合、依赖请求是否生效、归档启用状态或 Workspace 写资格作为权威决定。

### 7.2 新增或扩展的只读接口能力

- 项目级 Task 搜索必须接受受限 Task Key/标题条件、稳定游标和活动/归档范围，并返回匹配摘要及从虚拟根到目标父级的祖先链。
- 当前层查询必须保留稳定 Task Key 排序、生命周期范围、分页、图版本和依赖；结构化筛选可以由服务端完成或在完整加载的当前层投影上完成，但结果必须与同一权威快照一致。
- Task 作用域附件读取必须通过人类 Session、Project/Task 读取授权和当前 Workspace 版本暴露最小清单与内容，不复用设备 Bearer 或租约凭据。
- 新增接口必须使用稳定错误契约、TypeBox、OpenAPI、租户过滤和现有 request ID/审计边界；精确路径和 DTO 拆分留给独立规划。

### 7.3 客户端导航与交互状态

客户端可以维护以下非权威状态：

- 当前 user、project、活动/归档视图和父级作用域。
- 当前选中 Task、抽屉开关和抽屉内当前标签页。
- 面包屑祖先链。
- 每一层的筛选、DAG 视口、滚动和焦点恢复位置。
- 搜索条件、结果、分页和搜索前位置快照。
- 浏览器历史中可序列化的项目、父级和选择状态。
- 编辑草稿、脏状态、影响预览和用户尚未提交的确认。
- 当前意图幂等键及待确认版本；不得把 token、Cookie、Admin Mode 能力或 lease secret写入 URL 或持久浏览器存储。
- TanStack Query 缓存和 SSE 连接状态。

刷新可以丢弃未提交草稿，但存在脏表单时必须提供离开提示；任何草稿都不得自动提交或在另一项目/Task 中复用。

### 7.4 时间、身份和显示映射

- 服务端时间继续使用带 `Z` 的 RFC 3339 UTC；界面按设备系统时区显示，并在编辑时无损转换回 UTC。
- Membership/Role ID 通过当前项目资源显示名称、活动/移除/归档状态。历史 Owner 已移除时仍必须显示可追溯身份，不得误写成“未分配”。
- Task Key 是用户可识别的稳定定位符；内部 UUID 不作为主要导航文本，也不得接受来自其他项目的 UUID 绕过 Project Key/Task Key 解析。

### 7.5 持久化与迁移

M3 本身不需要新的客户端业务持久化。若实现搜索性能、祖先查询或附件代理需要数据库索引、投影或迁移：

- 必须从正式 version 3 向前应用、可重复且失败可诊断。
- 不得改写 Task、Project、Membership、Role、Workspace、评论、活动、通知、审计、Outbox、Key 或历史版本。
- 可重建查询投影不得成为第二写入事实；损坏或丢失时必须能从现有权威记录重建。
- 回滚采用停止新版本并 roll forward 修复，或在迁移前一致备份上恢复；不得通过生产 reset 恢复。

## 8. 异常、边界与恢复

- 未登录、Session 失效、Membership 非活动、项目归档、跨项目 Key/ID、无权 Task 或附件必须使用稳定的不可枚举/禁止语义，不得通过搜索结果、错误、SSE、URL 标题或缓存泄露资源存在性。
- 无项目、空项目、空当前层、无直接子任务、无搜索结果、无筛选结果、无评论、无活动和无通知必须提供明确空状态与恢复入口，不得残留上一项目或上一层数据。
- 无效、过深、已删除或已归档深链必须恢复到可解释的项目根、历史视图或不可用结果；不得自动选择同 Key 之外的任务。
- 服务端返回重复 Key、父级/祖先不一致、跨父依赖、自环、环、依赖端点缺失或 graph scope 不匹配时，客户端必须 fail closed并显示可诊断错误，不得渲染可能误导的部分 DAG。
- 分页或筛选只改变当前可见投影；隐藏节点相关依赖必须提示，不能改写、删除或反向显示原始边。
- Task/Graph/Workspace/评论/通知版本、影响令牌、Admin Mode 或权限漂移时，旧写入必须停止。界面保留安全草稿，重新获取权威事实并要求用户重新确认适用影响。
- SSE 与用户编辑并发时不得静默覆盖输入；若字段冲突不能自动合并，必须显示服务端当前值和本地未提交值，由用户重新编辑。
- 同一幂等请求结果未知时必须先重试同一负载或查询权威状态；不得生成新键并盲目重复创建、评论、依赖、完成或破坏性操作。
- Admin Mode 到期、被撤销或切换项目时，旧 ID 必须立即停止用于 Task 请求；界面不得自动重新开启。
- 归档、删除、移动、Owner 变化、级联重开和关注的影响预览发生漂移时必须重新预览。删除 Key 不匹配、子树含完成 Task、外部完成端点或无权限时必须稳定拒绝。
- 完成条件、最终服务端 Workspace 版本、活动租约或未提交客户端版本不满足或无法确定时，完成必须拒绝并给出恢复建议，不得默认填充安全答案，也不得在 UI 中显示为部分冻结。
- Workspace 清单文件在评论提交或附件打开前被删除、版本变化、哈希不匹配或权限撤销时必须拒绝；不得从对象存储猜测路径或绕过 Task 授权。
- Markdown、长标题、多语言、组合字符、长标签、移除 Owner、归档角色、无截止时间和无头像必须稳定呈现，不得破坏键盘顺序、布局或 HTML 安全。
- 网络中断、API 5xx、SSE 断开或浏览器刷新不得破坏已提交服务端事实。恢复后先重新读取项目、Task、图和 `actions`，再允许新的写入。
- M3 不提供任务删除恢复、归档恢复、单任务备份恢复或 Workspace 冲突选择；相应误操作只能依赖既定影响确认和未来 M6 项目级恢复能力。

## 9. 非功能需求

### 9.1 性能与规模

- 在参考服务器、初期负载和正常内网/VPN 条件下，当前层列表与详情服务端 P95 必须保持小于 500 ms，普通创建/更新小于 800 ms，200 节点局部 DAG 读取小于 800 ms。
- 数据返回后，选择、抽屉切换、筛选和层级切换的主要界面更新 P95 必须不超过 200 ms；暖缓存 Web 首次可交互必须小于 3 s。
- 200 同层节点和不同密度依赖必须完整可用，连续滚动/平移期间不得出现持续输入阻塞、错误选择、空白视口或节点/边错位。
- 项目 5,000 活动 Task、深度 20 和单层超过 200 不得破坏正确性。200 是 core 性能规模，不是领域硬限制；更大单层可以通过分页、搜索和筛选访问。
- 性能优化不得通过隐藏应显示的节点、丢弃有效边、下载全部项目正文、削弱权限检查或测量空数据达标。

### 9.2 可访问性与视觉

- 正式 Task UI 必须使用中文，并在至少 1280×720、100% 缩放的桌面视口完成 core 验收。
- 所有浏览、搜索、筛选、节点选择、抽屉、下降、面包屑、创建/编辑、影响确认、依赖、评论、通知和 Admin Mode 入口必须可通过键盘完成，焦点始终可见且关闭抽屉/对话后返回合理来源。
- 状态、展示类型、选择、阻塞、完成就绪、归档、危险程度和依赖方向不得只用颜色表达。
- DAG 节点和边必须提供可访问名称或等价文字关系，使不依赖视觉连线的用户可以理解 predecessor → successor。
- 非模态抽屉打开时不得使 DAG 重排或阻止选择同层其他节点；高影响确认可以使用可访问对话，但不得丢失当前层上下文。

### 9.3 安全、隐私和审计

- Web 继续使用 SameSite Cookie、Same-Origin 写入保护和项目范围 Admin Mode；所有 Task/附件接口必须服务端重新授权并带项目租户过滤。
- 不得把用户输入拼入任意 HTML、对象键、文件系统路径、查询结构或日志字段；Markdown 和 URL 必须使用安全白名单或等价清理。
- 高影响操作、成功/失败 Task 写入、Admin Mode 和评论隐藏继续由 M2 审计；M3 不创建可绕过审计的旁路。
- 普通日志、浏览器 URL、客户端遥测、错误通知和 SSE 不得包含秘密或不必要的完整正文。M3 不引入外部遥测、内容处理或云端依赖。

### 9.4 兼容性、发布与恢复

- Windows 11 x64 Chrome 和目标 macOS Apple Silicon Chromium 必须通过正式 Task UI core；Safari、Firefox 和较窄桌面视口可以作为 supplemental。
- 现有 M1 Web、认证/Pairing/Device/Workspace、API/OpenAPI、Worker、Workspace CLI、Compose 发布栈和精确 Task UI prototype 入口必须保持可观察兼容。
- 新增公共只读接口和任何迁移必须向后兼容；现有 M2 客户端无需修改即可继续调用原路径。
- 应用/API/Worker 重启和 SSE 重连不得破坏已提交事务。发布失败时必须能够回退 Web/API 版本；若包含向前迁移，则按迁移前备份和 roll-forward 规则恢复，不得 reset。
- 适用的格式、lint、构建、类型检查、单元/集成/浏览器测试、PostgreSQL、OpenAPI 和发布门禁必须通过；未具备外部环境的 supplemental 检查可以按 relaxed finding 规则处理，但 core 平台/行为不可省略。

### 9.5 可维护性与可观测性

- Task 查询、搜索、祖先链、依赖投影、操作输入和错误映射必须可以脱离视觉组件验证；正式业务规则不得只存在于 React 条件、CSS 或提示文本。
- M3 query key 必须按 user/project/Task/scope/资源类型稳定分区，登出、切换用户或失去项目权限时清除对应缓存和敏感草稿。
- API 日志继续使用 request ID、模块和稳定错误码；客户端错误必须显示用户可读消息和 request ID，但不得显示原始敏感响应。
- 不要求新增 Prometheus、集中日志、独立前端监控或缓存集群。

## 10. 初步实现方向与影响范围

- 在现有 `M1App` 已认证 shell 中增加项目 Task 导航和正式 M3 页面；项目治理与 Task 管理共享当前 Project、Membership、成员、角色和 Admin Mode 上下文。
- 在共享 contracts、Task query repository、应用服务和 Fastify routes 中补齐项目搜索、祖先链和人类 Session 下的 Task Workspace 只读附件适配；现有 M2 命令端点与领域服务保持原样。
- 在 `apps/web` 新建正式 M3 数据模型、query keys、路由/历史适配、DAG 页面、详情抽屉、操作表单、影响确认、评论/活动和通知组件。可以提取封存原型中的纯布局与状态不变量，但生产路径只能消费正式 API。
- 浏览数据流为“URL/当前项目 → 当前 scope query → DAG 投影 → 选择后详情/评论/活动”；搜索由服务端返回祖先链，SSE 只触发精确 query refetch。
- 写入数据流为“服务端 `actions` → 用户填写/预览 → 版本与幂等提交 → 服务端响应 → 精确失效/refetch”；高影响操作不得依赖客户端推算影响。
- 自动化重点覆盖 query/DTO、租户和 Session 授权、搜索祖先、Task Workspace 附件代理、M2 全操作输入映射、版本/幂等/SSE、路由恢复和原型交互不变量；真实浏览器覆盖 DAG、焦点、键盘、危险确认和 200 节点性能。
- 预计影响范围包括 `packages/contracts`、`packages/database` 的 Task 查询、`apps/api` Task routes/service、`apps/web` 正式 M3 与共享 M1 shell、相关 fixtures/tests、OpenAPI/参考验证文档；只有经规划证明必要时才修改 migration、性能脚本或发布验证。
- 主要风险包括完整 M2 操作面过宽导致状态漂移、当前 Task 查询加载全项目快照、200 节点 DAG 布局、深链与抽屉状态一致性、Admin Mode/版本并发、Workspace 附件 Session 适配、危险操作误确认和 SSE 覆盖草稿。
- 所有后续阶段必须保持以下跨阶段不变量：服务端是唯一业务/权限权威；任一时刻一幅当前 scope DAG；依赖只连接同父级且方向不反转；下降只通过专用操作；M2 写语义和冻结边界不变；高影响提交绑定同一预览；M1/prototype 保持可用；M4/M5/M6 不被提前实现；每个阶段结束时项目保持可构建且不会把半完成入口暴露为可用正式能力。
- 精确组件拆分、URL 格式、图布局算法、是否新增轻量路由依赖、查询索引和阶段数量属于独立规划决策，只要不改变本需求的可观察行为与不变量。
