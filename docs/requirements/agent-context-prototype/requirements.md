# Agent 上下文原型：需求

- 功能 ID：`agent-context-prototype`
- 需求状态：已确认，可进入独立规划
- 确认日期：2026-07-25

## 1. 背景与目标

NGAPD 的 Workspace Sync 原型已经完成 macOS 主体并等待集中 Windows 验证，Task UI 原型正在实现 macOS 主体。Agent Context 是第三个前置原型，也是三个原型进入最终 Windows 11 x64 集中验证前的最后一项主体工作。仓库当前只有 Agent Context 的验证说明、候选来源夹具、提示注入夹具和结果模板，没有上下文清单核心、预算裁剪、分页、渐进读取或 Agent 业务工具实现。

本原型必须验证以下产品假设：任务边界、分层 Workspace、角色、祖先、predecessor、任务关注和确认摘要能够形成来源清晰、低污染、权限受控的上下文；Agent 可以先获得可分页的引用清单，再按任务需要渐进读取内容；工作区中的任何文本都不能扩大工具权限。

本原型的目标结果是：

1. 使用确定性内存夹具和无头 TypeScript 验证入口，构造可重复的 Agent 上下文清单，不依赖登录、PostgreSQL、真实 Workspace、外部 API、AI 或 LLM。
2. 固定并验证来源组成、冲突优先级、稳定排序、游标分页、预算保护、裁剪原因、摘要来源和渐进读取边界。
3. 证明无关兄弟任务、递归关注链、未启用 Skill 和未获明确用户意图的其他用户级 Workspace 不会进入发现、搜索或默认上下文。
4. 证明提示注入文本只能作为非可信内容，不能改变底层授权、管理员模式、读写范围或人工确认要求。
5. 使用确定性的参考消费者从渐进读取结果生成结构化任务分析，验证上下文是否足以表达目标、约束、角色、相关历史与权限边界，而不评价某个真实模型的语言质量。
6. 在当前 macOS/Node 环境完成主体 core 证据并形成可追溯 `pass` 结果；将同一确定性 core 套件的 Windows 11 x64 执行保留为三个原型主体完成后的最终兼容门禁。

## 2. 范围

### 2.1 包含范围

- 复用并以增量方式扩展 Task UI 的确定性任务树、同级 DAG、Owner 和任务字段夹具，不修改 Task UI 的交互语义。
- 扩展 `prototypes/agent-context/fixtures/`，覆盖当前用户、项目成员、自我介绍、逻辑角色、主任务、多层活动祖先、已完成 predecessor、直接关注、关注环、长关注链、三级 Workspace 来源、摘要和显式附加来源。
- 实现可由自动化直接调用的确定性上下文清单核心和无头原型验证入口。
- 上下文来源的固定优先级、信任级别、稳定排序、权限依据、估算 token、版本、选择状态和排除或裁剪原因。
- 只返回引用和元数据的清单，以及与清单分离、每次重新授权的合成渐进读取操作。
- 绑定输入版本的不透明游标分页；同一版本的跨页结果不得重复、遗漏或重排。
- 系统安全规则、项目规则、当前任务和当前用户角色的预算保护；可选来源的确定性整项保留或排除。
- 当前用户绑定的全部逻辑角色、当前任务绑定角色的定义，以及“逻辑角色不授予权限”的边界。
- 当前任务活动祖先的当前信息和历史确认摘要、已完成 predecessor 的确认摘要，以及当前任务直接关注的一跳目标。
- 当前用户自己的用户级流程、规则和已启用 Skill；项目级规则、参考资料和已启用 Skill；当前任务级目录与按需读取的合成文本。
- 图片只以元数据或明确引用进入清单；不把二进制正文装入默认上下文。
- 其他用户用户级 Workspace 的默认排除，以及“明确目标和目的 + 底层允许”时的受控只读场景。
- `agent_provided`、`user_provided` 和 `system_fallback` 三类确认摘要的来源、版本和工作周期。
- 提示注入前后的授权对照、确定性结构化任务分析、性能测量和原型结果记录。
- 当前 macOS/Node 主体证据，以及三个原型主体完成后的 Windows 11 x64 core 兼容验证约束。

### 2.2 不包含范围

- 不新增或修改正式 Agent Session、Context Manifest、KnowledgeEntry、Task Follow 或搜索数据库表，不创建 migration。
- 不实现正式 Agent Context API、Web 页面、Workspace CLI 业务命令、MCP 业务工具、Agent 宿主配对或本地 IPC 能力。
- 不连接真实账号、真实项目、真实任务、真实 Workspace、本地用户文件或生产数据。
- 不调用外部 API、AI 或 LLM，不向外发送业务内容，不选择或评测具体模型。
- 不生成自由文本 AI 摘要；`agent_provided` 仅作为带固定合成正文和来源的夹具类型。
- 不执行 Task、Workspace 或项目数据写入，不进入管理员模式，不取得真实写入租约，不验证任务管理提案的 UI。
- 不修复或扩大当前生产 `resolveWorkspaceReadAccess` 的跨用户读取能力；该实现与 D-050 的最终统一留待正式 Agent/API 集成。
- 不实现语义向量检索、嵌入、自动相关性模型、全文搜索服务、缓存集群或大规模知识库。
- 不执行 Skill 脚本，不增加 Skill 签名、发布审批或额外能力系统。
- 不修改 Workspace Sync 和 Task UI 已冻结或正在实现的需求、工作流结论和主体行为。

## 3. 已确认的项目事实与约束

- 项目采用 pnpm workspace、TypeScript 5.9 和 Node 24；共享领域逻辑、契约与测试夹具分别位于 `packages/domain`、`packages/contracts` 和 `packages/test-fixtures`。
- 前置原型可以使用内存数据和测试夹具，但不得弱化服务端权威、权限、版本、确认或单写入者约束。
- Agent 工具采用 MCP 风格结构化契约和 stdio 优先方向，但当前正式 CLI 仍没有 `connect_task`、`get_context_manifest` 或业务级渐进读取工具。
- Agent 始终代表当前登录用户；提示、Skill、角色描述、评论或 Workspace 文件均不能授予权限。
- 一个 Agent 会话同一时间最多有一个当前可写 Workspace；其他相关 Workspace 只能作为只读来源。该原型不建立真实会话或写租约。
- 默认冲突优先级为：系统安全与工具规则 > 项目级通用规则 > 当前任务正式信息 > 用户个人流程。当前 `context-sources.json` 将当前任务排在项目规则之前，属于需要由本原型修正的夹具漂移。
- 当前任务上下文默认包含：项目规则和已启用 Skill、当前任务完整信息、当前用户项目自我介绍与其全部绑定角色、用户个人流程和已启用 Skill、活动祖先当前信息与历史摘要、已完成 predecessor 摘要、直接关注的一跳来源，以及当前任务级目录和选定文件。
- 当前任务的关注关系只展开一跳并按稳定 Task ID 去重；关注可以成环，但不递归，不授予写权限，也不改变依赖、状态、Owner 或完成计算。
- 无关兄弟任务、未显式选择的其他任务原文、递归关注目标、未启用 Skill、大型二进制正文、无引用的归档任务和其他用户用户级 Workspace 默认排除。
- D-050 要求其他用户的用户级 Workspace 不进入 Agent 发现、搜索或默认上下文；只有用户明确指定目标和目的且底层读取允许时才可只读。
- 当前 `packages/domain/src/authorization.ts` 对非本人用户级 Workspace 读取采取比 D-050 更严格的直接拒绝。原型不得借机扩大生产授权，只通过显式底层授权事实夹具验证 Agent 附加门禁。
- 同名 Skill 冲突时项目级来源优先于当前用户的用户级来源；发现或加载 Skill 不增加工具能力。
- 完成摘要是独立、版本化的 KnowledgeEntry 产品概念；来源为 `agent_provided`、`user_provided` 或 `system_fallback`，`SUMMARY.md` 只是只读投影。服务端不得调用模型生成 AI 摘要。
- 上下文清单应返回引用而不是一次返回全部正文，并带来源、摘要、大小、优先级和信任边界。
- MVP 对 Agent 上下文清单的性能目标是 P95 小于 1 秒，不包含按需文件下载。
- 工作区内容、评论、角色提示和外部文档必须按非可信输入处理；所有工具执行必须重新授权。
- 原型结论只能是 `pass`、`fail` 或 `inconclusive`；结果记录必须包含环境、Git commit、夹具版本、预算、稳定排序、权限依据、裁剪原因、排除项、注入前后授权和摘要来源。
- Workspace Sync 与 Task UI 工作流已经固定“先完成三个 macOS/主体结果，再集中执行 Windows 11 x64 core”的顺序。主体 `pass` 可以解锁集中验证，但 Windows core 通过前各相关工作流不得最终封存。
- 当前 Task UI 文件和 `packages/test-fixtures/src/task-graph*` 存在用户正在进行的实现改动；Agent Context 后续实现必须保留这些改动，只做可区分的增量集成。
- 项目 Agent 流程文档根目录为 `docs/requirements`；新功能使用独立目录和 schema `3.2` 工作流合同。
- 本需求确认时项目分支为 `prototype`，基线提交为 `bcae1aa1c66081c67ecbb9f6391b9613927f775a`。

## 4. 交付与验证策略

- 用户明确选择 `relaxed`。
- 实现可以先于测试，不要求人为制造 red-first 基线。
- 所有 core 验收、权限与隐私边界、提示注入隔离、确定性、预算保护、分页正确性、P95 性能、构建兼容、结果可追溯性和 Windows 最终兼容门禁仍然阻塞对应主体阶段或整个运行完成。
- supplemental 异常只有在独立证据证明其不影响任何 core 行为、项目硬门禁、安全、隐私、兼容或可构建性时，才可作为稳定 `FND-I-*` report-only finding 保留；不得在失败后把 core 项降级为 supplemental。
- 当前优先完成可在 macOS/Node 环境执行的确定性主体。主体 core 全部通过后，可以形成 Agent Context 主体 `pass` 结果并解锁三个原型的集中 Windows 验证。
- Windows 11 x64 上的同一确定性 core 套件继续属于最终 core 门禁。环境不可用时，本运行可以安全停在 `awaiting_next_phase`，但不得生成最终 `change-0.md`、有效需求快照或宣告整个工作流完成。

## 5. 功能需求

- `FR-001`：原型必须提供可由自动化和无头 Node 入口直接调用的确定性上下文核心；不得要求登录、PostgreSQL、真实 Workspace、Web 浏览器或外部网络服务。
- `FR-002`：原型夹具必须具有显式 schema 版本和稳定合成 ID，并在相同夹具版本、输入、预算、页大小和游标下产生完全相同的清单、读取结果和结构化任务分析。
- `FR-003`：夹具必须覆盖当前用户、项目成员、自我介绍、当前用户绑定角色、当前任务绑定角色、主任务、多层活动祖先、同级 DAG、已完成 predecessor、无关兄弟、直接关注、关注环、长关注链、三级 Workspace 来源、摘要和图片元数据。
- `FR-004`：原型必须在生成清单前验证重复来源 ID、未知来源类型、无效优先级、负数或非整数 token 估算、缺失版本、无效任务引用、跨项目关注、无效摘要来源和不一致权限事实；无效输入不得产生部分可信清单。
- `FR-005`：默认候选来源必须覆盖系统安全与工具规则、项目级规则/启用 Skill/相关参考、当前任务正式信息、当前用户自我介绍与角色、当前用户个人流程/启用 Skill、活动祖先当前信息与历史摘要、已完成 predecessor 摘要、直接关注的一跳来源、当前任务级目录/选定文件和用户显式附加来源。
- `FR-006`：系统安全和工具权限规则必须具有最高冲突优先级、明确的可信来源，并且不得因低预算、分页或任何 Workspace 内容而被静默覆盖或降级。
- `FR-007`：项目级规则必须在冲突时优先于当前任务正式信息和用户级个人流程；当前任务正式信息必须优先于用户级个人流程。原型必须修正现有候选来源夹具中与该顺序冲突的优先级。
- `FR-008`：当前任务来源必须包含 Task Key、标题、统一正文、显式/有效 Owner 与继承来源、任务逻辑角色、状态、UTC 截止时间、标签、展示类型、父子关系、依赖、关注和当前权限的合成事实。
- `FR-009`：角色上下文必须包含当前用户在项目中绑定的全部逻辑角色及当前任务绑定角色的定义，并保留角色名称、能力、责任边界、限制和 Agent 提示来源；任何角色均不得改变授权结果。
- `FR-010`：用户级自动发现只能包含当前用户自己的流程、规则和已启用自用 Skill；其他用户的用户级来源不得进入默认候选、搜索结果或清单。
- `FR-011`：活动祖先来源必须按从近到远或另一种明确记录且稳定的关系顺序包含当前标题、正文、角色、状态和关键已确认决定；若存在相关历史完成摘要，必须保留其独立来源和版本。
- `FR-012`：predecessor 来源只能自动包含当前任务已完成 predecessor 的已确认摘要；未完成、无关或不满足当前用户读取权限的 predecessor 不得自动提供正文。
- `FR-013`：当前任务直接关注的目标必须在当前用户原有读取权限内进入可发现清单，并按稳定 Task ID 去重；被关注任务自身的关注目标不得递归展开，关注环和长关注链不得扩大来源集合。
- `FR-014`：当前任务和获准关注目标的任务级 Workspace 默认只提供目录、文本元数据、图片元数据和明确引用；正文必须通过渐进读取取得，大型二进制正文不得进入清单或读取结果。
- `FR-015`：用户显式加入的其他任务摘要、项目资料或参考文件必须记录加入原因、来源、版本和底层授权，且不得因显式加入而获得高于系统安全规则的优先级。
- `FR-016`：原型必须稳定排除无关兄弟任务完整内容、未选择的其他任务 Workspace 原文、递归关注来源、未启用 Skill、整个项目历史评论、大型二进制正文和无引用的归档任务。
- `FR-017`：其他用户的用户级 Workspace 只有在当前请求同时携带明确目标和读取目的、底层读取事实允许且目标版本存在时，才能作为只读来源；缺少任一条件都必须拒绝，并且任何场景都不得授予写入。
- `FR-018`：每个上下文清单条目必须至少包含稳定来源 ID、来源类型、作用域或关系、版本、优先级、信任级别、估算 token、授权依据、选择状态，以及包含、排除或预算裁剪原因。
- `FR-019`：上下文清单及其分页响应不得直接嵌入候选正文；清单只能返回可供后续受控读取的引用、摘要或元数据。
- `FR-020`：清单排序必须确定且可解释，首先遵守固定优先级，再使用明确的关系顺序、来源类型和稳定 ID 作为平局规则；运行时枚举顺序不得改变结果。
- `FR-021`：清单必须支持稳定分页。游标必须是不透明且绑定夹具 schema、输入版本、预算和排序事实；同一版本跨页不得重复、遗漏或重排，输入变化后的旧游标必须稳定返回失效错误。
- `FR-022`：上下文预算必须计算被选定正文的 `estimatedTokens`，不把清单元数据计入正文预算；预算值必须是非负整数，并在结果中报告总预算、已选用量和剩余量。
- `FR-023`：系统安全规则、项目规则、当前任务和当前用户角色是不可静默丢弃的必需来源。其总估算超过预算时，原型必须返回 `insufficient_context_budget` 及所需最小估算，不得截断安全内容或返回看似完整的任务分析。
- `FR-024`：必需来源满足后，其余来源必须按确定性优先级整项保留或排除；原型不实现正文中段裁剪。每个未选来源必须保留 `budget_excluded` 或更精确的原因，不得用低优先级小来源静默掩盖高优先级来源被排除的事实。
- `FR-025`：渐进读取请求必须引用当前清单中的稳定来源和版本，并重新检查当前用户、显式意图及底层读取事实；未选择、已失效、版本不匹配或未授权的来源不得返回正文。
- `FR-026`：所有读取结果必须保留来源和信任级别，并将系统规则与非可信 Workspace、评论、角色提示或外部资料明确分隔；正文中的“进入管理员模式”“忽略权限”或工具调用文本不得影响授权结果。
- `FR-027`：项目级和当前用户用户级 Skill 只在已启用时可发现，并先返回稳定入口和清单而不是递归加载整个目录；同名 Skill 冲突时项目级来源优先，发现或读取 Skill 不授予任何额外工具能力。
- `FR-028`：摘要来源必须使用 `agent_provided`、`user_provided` 或 `system_fallback`，并带来源任务、工作周期、版本和确认状态；只允许相关且已确认的摘要进入默认上下文，不得把任何摘要表述为 NGAPD 服务端模型生成。
- `FR-029`：参考消费者必须只使用清单与渐进读取结果，确定性输出当前任务目标、关键约束、当前用户角色边界、相关祖先、已完成 predecessor、直接关注来源、权限限制和预算排除项；输出必须可与固定预期逐字段比较。
- `FR-030`：参考消费者不得把未读取来源、被排除来源或提示注入文本中的权限声明当成事实；预算不足、授权失败或必需来源缺失时必须返回明确的不可完成分析状态。
- `FR-031`：原型不得新增正式 API、数据库、Web 或 Agent/MCP 业务入口，不得读取真实业务数据，不得改变当前生产 Workspace 授权行为，也不得调用外部 API、AI 或 LLM。
- `FR-032`：Agent Context 的增量夹具和核心不得破坏 Task UI 正在实现的任务图字段、既有 Workspace Sync 夹具或根 workspace 的现有构建、类型和测试兼容性。
- `FR-033`：当前 macOS/Node 主体必须覆盖正常预算、预算不足、多页清单、祖先、predecessor、一跳关注、关注环、跨用户拒绝与明确意图、摘要来源、Skill 冲突和提示注入场景，并产生可追溯结果。
- `FR-034`：在规定主体规模上，上下文清单生成 P95 必须小于 1 秒；测量不得包含渐进正文读取，也不得通过删除必需来源、减少既定任务关系或跳过授权检查来达标。
- `FR-035`：三个原型主体完成后，必须在 Windows 11 x64 使用同一夹具版本和同一确定性 core 套件重复兼容验证；该门禁未通过前，本工作流不得最终封存。
- `FR-036`：每次主体或最终平台执行必须在 `prototypes/agent-context/results/` 新增独立结果记录，结论只能是 `pass`、`fail` 或 `inconclusive`，并保留环境、commit、夹具、预算、排序、分页、权限、裁剪、注入对照、摘要来源和证据位置。

## 6. 用户流程或调用流程

### 6.1 生成上下文清单

1. 验证者选择固定夹具版本、当前用户、主任务、预算和页大小。
2. 原型校验用户、任务关系、Workspace 来源、摘要、权限和 token 估算。
3. 原型生成全部有资格候选，先应用底层读取和 Agent 附加发现门禁，再应用固定优先级和预算规则。
4. 原型返回第一页引用清单、预算汇总和不透明下一页游标；不得返回候选正文。
5. 验证者使用游标读取后续页面，跨页结果保持完整、无重复且顺序稳定。

### 6.2 渐进读取与任务分析

1. 参考消费者查看清单中的来源、摘要、信任级别、大小和排除原因。
2. 消费者按固定场景选择必要来源并发起合成读取。
3. 每次读取重新校验用户、显式意图、底层授权、来源版本和清单成员资格。
4. 消费者从实际读取内容生成结构化任务分析，并列出未读取或预算排除项。
5. 原型逐字段比较目标、约束、角色、关系、权限和排除项与固定预期。

### 6.3 预算不足

1. 验证者将预算设置为低于必需来源总估算。
2. 原型返回 `insufficient_context_budget`、必需来源清单和所需最小估算。
3. 原型不得返回伪完整分析、截断安全规则或用可选来源替代必需来源。
4. 提高预算后以相同输入重试，原型重新生成完整、确定的清单，不保留半完成状态。

### 6.4 一跳关注与跨用户读取

1. 主任务的直接关注目标在底层允许时进入可发现清单。
2. 关注目标自身的关注关系不再展开；关注环和长链按稳定 Task ID 去重并止于一跳。
3. 其他用户用户级 Workspace 在默认请求中完全不可发现。
4. 请求只有在显式指定目标和目的且底层允许时，才能得到指定来源的只读引用；缺少任一条件即稳定拒绝。
5. 任何关注或跨用户读取都不产生写权限、管理员模式或租约能力。

### 6.5 提示注入对照

1. 验证者先用不含注入正文的相同授权事实生成清单和读取决定。
2. 加入 `workspace-injection.md` 作为非可信任务材料并重复操作。
3. 原型可以返回该材料的普通内容引用，但其来源和信任级别必须明确。
4. 注入前后的底层授权、管理员模式、可读/可写范围和确认要求必须完全相同。

### 6.6 主体与集中平台验证

1. 在当前 macOS/Node 环境执行全部主体 core 场景和清单性能测量。
2. 所有主体 core 通过后新增一份 `pass` 结果，Agent Context 主体视为完成并解锁集中 Windows 验证。
3. 三个原型主体完成且 Windows 11 x64 入口可用后，以相同夹具版本执行确定性 core 套件。
4. Windows core 通过后，本工作流才具备最终封存条件；环境缺失时安全等待，不用 finding 替代。

## 7. 数据、接口与状态

### 7.1 原型输入

原型输入至少包含：

- `schemaVersion`、夹具版本和稳定场景 ID。
- 当前 actor、活动状态、项目 Membership、自我介绍和绑定逻辑角色。
- 当前项目、主任务、任务版本、祖先、predecessor、关注和权限事实。
- 用户级、项目级和任务级 Workspace 合成来源及其版本、类型、大小、信任和启用状态。
- 摘要来源、工作周期、版本、确认状态和合成正文。
- 其他用户读取所需的明确目标、目的和底层授权事实。
- `budgetTokens`、页大小和可选游标。

输入只包含合成数据，不包含真实用户 ID、真实文件路径、凭据、令牌或业务正文。

### 7.2 候选来源与清单条目

候选来源至少具有：

- 稳定 `sourceId` 与来源类型。
- 用户、项目、任务或系统作用域，以及祖先/predecessor/follow 等关系。
- 来源版本、信任级别、优先级和 `estimatedTokens`。
- 底层授权事实、Agent 发现要求、启用状态和显式加入原因。
- 合成正文引用或图片元数据；正文不嵌入最终清单。

清单条目在候选字段基础上增加：

- 稳定排序键或足以解释排序的字段。
- `included`、`excluded` 或等价选择状态。
- `mandatory` 标记。
- 授权依据和预算选择或排除原因。
- 可供受控读取的版本化引用。

### 7.3 分页与游标

- 第一页由规范化输入、预算、固定排序和页大小生成。
- 游标是不透明值，并绑定 schema、输入版本、预算、页大小和排序事实。
- 同一版本的所有页面组合后必须等于未分页的同一清单。
- 输入、版本、预算、排序或页大小变化后，旧游标返回稳定失效错误，不尝试猜测续页位置。
- 分页是只读计算，不建立服务端会话或持久化游标。

### 7.4 预算状态

- `budgetTokens` 是非负整数。
- `selectedTokens` 是被选正文估算之和，不大于预算。
- `remainingTokens = budgetTokens - selectedTokens`。
- 必需来源总量单独计算为 `minimumRequiredTokens`。
- 必需来源不足时返回错误，不产生成功清单或结构化分析。
- 可选来源按固定优先级整项选取；未选条目仍可在清单诊断视图中保留元数据和排除原因，但不得被参考消费者当作已读取内容。

### 7.5 渐进读取接口

渐进读取的概念输入包括 actor、清单版本、来源 ID、来源版本和可选显式读取意图；输出包括合成正文或元数据、来源、信任级别和授权结论。

- 只允许读取当前有效清单中可读的版本化来源。
- 每次调用重新计算底层授权和 Agent 附加门禁。
- 图片返回元数据或明确引用，不返回二进制正文。
- 错误不得泄露未授权正文或其他用户来源的可枚举信息。
- 该接口仅为原型内纯函数或无头适配边界，不是正式公共 API。

### 7.6 参考消费者输出

结构化分析至少包含：

- 当前任务标识、目标和关键约束。
- 当前用户角色能力和责任边界。
- 相关活动祖先、已完成 predecessor 和直接关注来源。
- 生效的系统、项目、任务和用户规则来源。
- 当前读写、管理员模式和确认限制。
- 未读取、未授权、预算排除或版本失效的来源。
- 分析状态：`complete` 或明确的不可完成原因。

### 7.7 持久化、迁移与并发

本原型不新增持久化状态、数据库表、migration、外部作业或多写者。所有结果由不可变合成输入纯计算得到；并发写入、数据迁移和生产回滚不适用。并行执行相同场景必须得到相同结果，且不得共享会改变输出的全局可变状态。

## 8. 异常、边界与恢复

- 重复来源 ID、无效来源类型、无效 token、缺失版本、无效任务关系、跨项目关注、不受支持摘要来源或互相冲突的权限事实必须稳定拒绝，并指出可定位的合成输入问题。
- 必需来源总估算超过预算时必须返回 `insufficient_context_budget`；提高预算后可从相同不可变输入重新执行，不存在部分提交或状态恢复。
- 游标与当前 schema、输入、预算、页大小或排序事实不匹配时必须返回稳定的游标失效错误；调用者从第一页重新开始。
- 来源在清单生成后版本变化时，渐进读取必须返回来源版本失效，不得读取新正文并假装仍属于旧清单。
- 其他用户来源缺少明确目标、目的或底层允许时必须返回不泄露正文的拒绝；不得通过错误差异枚举其他用户的 Workspace 内容。
- 当前用户不是活动项目成员、目标任务不可读或关注跨项目时，对应项目/任务来源不得进入清单。
- 未启用 Skill、未确认摘要、未完成 predecessor、无关兄弟任务和递归关注目标必须排除，并提供稳定分类原因。
- 提示注入正文可以被正常引用或读取，但授权、管理员模式、写入、租约和确认决定必须与没有该正文时完全一致。
- 参考消费者缺少任何必需来源、遇到读取拒绝或预算失败时必须输出不可完成状态，不得猜测任务目标或权限。
- P95 性能不达标、确定性漂移、跨页遗漏/重复、权限扩大、提示注入改变授权或参考分析使用未读来源时，主体结果必须为 `fail`；证据不足时为 `inconclusive`。
- macOS 主体完成而 Windows 入口不可用时，保存完整主体结果并安全等待；不得把 Windows core 降级为 supplemental 或用 macOS 重复执行替代。
- 本功能不涉及生产数据写入、迁移或不可逆操作。实现恢复边界是移除或禁用隔离的 Agent Context 原型入口和增量夹具，同时保留 Task UI、Workspace Sync 和用户已有改动；不得以清理原型为由删除共享用户工作。

## 9. 非功能需求

### 9.1 确定性与性能

- 相同 schema、夹具、用户、任务、授权、预算、页大小和游标必须产生逐字段相同的规范化结果。
- 在主体规模下，上下文清单生成 P95 必须小于 1 秒，不包含渐进正文读取。
- 主体规模至少覆盖 Task UI 的深树、200 同级任务和密集 DAG，以及 Agent Context 的角色、祖先、predecessor、一跳关注、关注环、三级 Workspace 和摘要来源。
- 性能测量必须记录环境、输入规模、预算、页大小、重复次数或等价统计依据和观察结果。
- 性能优化不得牺牲必需来源、授权复核、稳定顺序、排除原因或跨页完整性。

### 9.2 安全与隐私

- 原型只能使用合成数据；结果不得包含真实用户 ID、真实个人路径、凭据、令牌、真实 Workspace 正文或外部发送内容。
- 其他用户用户级来源默认不可发现；拒绝结果不得泄露可用于枚举内容的摘要、路径或正文。
- 系统规则必须与所有非可信来源明确分隔；工具授权不得依赖参考消费者是否正确理解正文。
- 原型不得进入管理员模式、取得真实租约、写入任何 Workspace 或更改生产权限策略。
- 任何安全、隐私、授权或提示注入异常均为 core，不得作为 relaxed 模式 report-only finding。

### 9.3 兼容性与可维护性

- 原型必须保持根 workspace、受影响共享包和现有 Task UI/Workspace Sync 夹具的构建、类型和适用自动化兼容。
- Agent Context 的新增类型和生成逻辑必须与 Task UI 正在演进的任务夹具增量集成，不得覆盖、回退或重新定义其字段。
- 关键排序、授权门禁、预算、分页和参考分析必须可脱离人工观察直接验证，不得只存在于输出文本或结果 Markdown 中。
- 当前主体运行于 macOS/Node 24；最终兼容环境为 Windows 11 x64/Node 24。
- 本原型不引入外部运行时服务、生产缓存、后台任务或新的部署组件。

### 9.4 结果与运维

- 每次执行必须新增结果记录，不覆盖历史结果。
- 结果结论只能为 `pass`、`fail` 或 `inconclusive`，并明确主体或最终平台范围。
- 结果必须遵循 `prototypes/agent-context/results/README.md` 的字段约定，并能追溯到夹具版本和验证证据。
- 若原型结论要求改变 ADR-010、ADR-012、D-050、上下文优先级或 Agent 契约，必须另行提出需求/ADR 变更，不得只在原型实现中静默偏离。
- 不要求生产监控、告警、备份或恢复演练，因为原型不持久化业务状态。

## 10. 初步实现方向与影响范围

- 在 `packages/test-fixtures` 中以可区分的增量扩展 Agent Context 合成来源、角色、关系、摘要和授权场景，复用 Task UI 任务图而不修改其 UI 语义。
- 将候选发现、底层/Agent 双层门禁、稳定排序、预算选择、游标分页、渐进读取和参考消费者保持为可测试的纯 TypeScript 职责；精确模块位置由后续规划基于依赖方向决定。
- 在 `prototypes/agent-context` 保留人可读夹具规范、注入样例、无头入口说明和不可覆盖的结果历史。
- 通过固定规范化输出或等价机制比较清单、跨页组合、读取结论和结构化任务分析；不引入真实模型来判断正确性。
- 现有 `context-sources.json` 的优先级漂移应在原型夹具范围内修正；不得借此改写已确认的产品优先级。
- D-050 的跨用户显式意图场景通过“底层读取允许/拒绝”合成事实验证 Agent 附加门禁；当前更严格的生产 resolver 保持不变，避免在原型内扩大真实权限。
- 预计影响范围限于 Agent Context 原型目录、共享测试夹具或新增的合适共享纯模块、相关自动化、结果证据及本功能工作流文档；不应修改数据库、API、Web、Workspace 同步协议或正式 MCP 工具。
- 主要风险是优先级与夹具漂移、预算规则产生伪完整上下文、游标在版本变化后续读错误、关注环递归、跨用户来源泄露、提示注入影响授权，以及对正在变更的 Task UI 共享夹具发生文件所有权重叠。
- 所有后续实现阶段必须保持以下跨阶段不变量：安全规则不可丢弃；项目规则优先于任务和用户流程；清单不嵌入正文；读取每次重新授权；其他用户来源默认不可发现；关注只展开一跳；角色和 Skill 不授予权限；服务端不调用模型；不修改生产权限；不接触真实数据；Task UI/Workspace Sync 行为不回归；主体先完成，Windows core 最后集中验证。
