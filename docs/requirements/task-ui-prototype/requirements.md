# 平铺树状 Task UI 原型：需求

- 功能 ID：`task-ui-prototype`
- 需求状态：已确认，可进入独立规划
- 确认日期：2026-07-25

## 1. 背景与目标

NGAPD 已完成 Workspace Sync 原型的 macOS 主体实现，Task UI 是当前下一项前置原型，也是后续 Agent Context 原型及三个原型集中 Windows 验证的前置输入。仓库目前只有 Task UI 的验证说明、确定性数据规范、最小宽层级夹具和结果模板；正式 Web 仍只提供账号、设备配对和设备管理，没有可执行的任务浏览界面。

本原型必须验证假设 H-005：不依赖语义缩放、无限画布或递归嵌套图，用户仍可通过“当前父级作用域的一幅 DAG + 选中任务详情抽屉 + 直接子任务列表 + 面包屑和返回上一级”理解深层任务分解与同级依赖，并在单层 200 个任务时保持可用。

本原型的目标结果是：

1. 在现有 React Web 工程中提供一个使用确定性内存夹具、无需真实 Task API 或数据库的可执行 Task UI 原型。
2. 验证虚拟项目根、深层任务树、单父级局部 DAG、任务详情抽屉、直接子任务列表、搜索、筛选和层级恢复的交互一致性。
3. 在当前 macOS Apple Silicon 的真实 Chromium 浏览器上完成主体功能、键盘可达性和 200 节点性能验证并形成可追溯结果。
4. 把 Windows 11 x64 的真实浏览器验证保留为三个原型主体完成后的最终 core 兼容门禁，不用该外部条件阻塞当前可在 macOS 完成的主体工作。

## 2. 范围

### 2.1 包含范围

- 在现有 `apps/web` React/Vite 应用中增加隔离的 Task UI 原型入口；入口使用确定性内存数据，不要求登录、PostgreSQL 或 Task API。
- 保持现有账号注册、登录、退出、设备配对和设备撤销界面的现有行为。
- 从 `prototypes/task-ui/fixtures/dataset.json` 的固定 seed 和 profile 生成稳定 Task Key、父子关系、同级依赖及完整展示字段。
- 覆盖 `deep-tree`、`wide-siblings` 和 `dense-dag` 三个数据 profile，包括 8 层深树、200 个直接子任务和 36 节点较密集无环依赖。
- 左侧只显示当前父级作用域的一幅有限 DAG；虚拟项目根作用域显示顶层任务，普通任务作用域显示该任务的直接子任务。
- DAG 必须同时表达全部可见同级任务节点、孤立节点和 predecessor → successor 有向依赖，不显示跨父级依赖。
- 未选择任务时只显示 DAG；选择 DAG 节点后，从右侧打开非模态详情抽屉。
- 详情抽屉展示任务详情、直接子任务列表，以及唯一用于下降层级的“进入子任务视图”按钮。
- 抽屉关闭、切换选择、进入子任务视图、面包屑、返回上一级、搜索定位和返回搜索前位置的状态管理。
- 按有效 Owner、逻辑角色、有效状态、截止时间和标签过滤当前 DAG。
- 普通、冲刺、里程碑三种只改变外观的展示类型。
- 中文桌面界面、键盘可达、可见焦点，以及颜色之外的状态和展示类型区分。
- 当前 macOS Apple Silicon 真实 Chromium 主体验证、结果记录、截图或等价可视证据，以及性能测量。
- 三个原型主体完成后的 Windows 11 x64 真实浏览器 core 验证入口和最终完成约束。

### 2.2 不包含范围

- 不实现正式 M1、M2 或 M3 的 Project/Task API、数据库持久化、任务创建或编辑、权限执行、评论、通知、活动流、任务完成、重新打开、归档或删除。
- 不修改现有同步原型使用的最小生产 `TaskStatusSchema` 来承载原型展示语义；原型使用独立且与产品基线一致的夹具语义。
- 不实现真实任务写入、服务端搜索、服务端分页、实时更新、多人协作或乐观并发处理。
- 不实现语义缩放、无限画布、递归嵌套图、节点内子图、自动任务排期、复杂动画或第二幅同时可见的 DAG。
- 不建立独立前端微应用、SSR 应用或本地 Workspace GUI。
- 不把直接子任务列表变成第二个导航树或第二幅 DAG；列表行本身不承担下降层级操作。
- 不把 URL 深链、刷新后恢复选中状态、浏览器前进/后退集成作为本原型 core 验收；正式路由属于后续 M3。
- 不把移动端、平板布局、低于 1280×720 的响应式体验、Safari、Firefox 或其他浏览器纳入主体 core 验收。
- 不调用外部 API、AI 或 LLM，不处理真实项目业务内容。

## 3. 已确认的项目事实与约束

- 项目采用 pnpm workspace、TypeScript 5.9、React 19、Vite 和 TanStack Query；Web 位于 `apps/web`。
- ADR-008 要求使用现有 React/Vite Web、不建立独立前端微应用；当前层任务使用虚拟化或等价渲染裁剪，依赖只布局当前父级作用域。
- 初版任务结构是“任务树 + 每个父节点内部的一张同级 DAG”。虚拟项目根没有 Task Key，顶层任务是它的直接子任务。
- 依赖只能连接同一父级作用域的直接子任务，方向为 predecessor → successor，任一作用域内不得成环。
- 当前 Web 只包含账号和 Workspace 设备访问界面，不包含路由器、Task 页面、DAG 布局或列表虚拟化实现。
- 当前 `packages/contracts/src/tasks.ts` 仅包含 Workspace Sync 所需的最小 Task 摘要和状态骨架，不足以表达 Task UI 的完整展示字段。
- 当前 `packages/test-fixtures/src/task-graph.ts` 只生成一个父任务和默认 200 个直接子任务，字段仅覆盖 Key、父 Key、标题和展示类型。
- 原型数据规范固定 seed `20260724`、Project Key `ZERO`、三个 profile、三种展示类型、四种有效展示状态和四类必备标签。
- 产品基线要求详情展示标题、正文、显式/有效 Owner 及继承来源、逻辑角色、有效状态、本地化截止时间、展示类型和子任务统计。
- 产品基线要求支持按有效 Owner、逻辑角色、状态、截止时间和标签过滤，并按 Task Key 或标题搜索定位到对应层级。
- 任务 UTC 截止时间必须按设备系统时区显示；原型不得把本地显示值当成新的权威时间。
- 普通、冲刺、里程碑只改变外观，不改变选择、导航、依赖、状态或过滤语义。
- 当前交互目标是数据就绪后主要界面更新不超过 200 ms；Web 暖缓存首次可交互目标小于 3 s。
- 初期规模按单项目 5,000 个活动任务、单父级 200 个直接子任务验收；200 不是产品硬限制。
- UI 必须优先满足中文界面、键盘可达、可见焦点和颜色之外的状态区分。
- 前置原型可以使用内存数据和测试夹具，但不得把夹具规则静默提升为服务端权威，也不得弱化同级依赖、权限、版本或服务端权威约束。
- `prototypes/task-ui/results/` 的真实执行记录必须包含结论、Git commit、浏览器、分辨率、缩放、硬件摘要、数据 profile、操作路径、测量方法、结果和可追溯视觉或性能证据。
- Workspace Sync 当前运行明确等待 Task UI 与 Agent Context 主体结果，以及最后集中的 Windows 11 x64 实机验证。
- 项目 Agent 流程文档根目录为 `docs/requirements`；新功能使用 schema `3.2` 的独立目录。
- 本需求确认时项目基线为 Git commit `bcae1aa`，分支为 `prototype`。

## 4. 交付与验证策略

- 用户明确选择 `relaxed`。
- 实现可以先于测试，不要求人为制造 red-first 基线。
- 所有 core 验收、交互正确性、键盘可达性、非颜色状态、性能硬门槛、可构建性、现有 Web 兼容、安全、恢复和 Windows 最终兼容门禁仍然阻塞相应阶段或整个运行完成。
- supplemental 异常只有在独立证据证明不影响交付行为时，才可作为稳定 `FND-I-*` report-only finding 保留；不得在失败后把 core 项降级为 supplemental。
- 当前优先完成可在 macOS Apple Silicon 上完成的实现、自动化和真实 Chromium 主体验证。macOS 主体达到本需求的主体退出条件后，可以形成 Task UI 主体 `pass` 结果并继续 Agent Context 原型。
- Windows 11 x64 真实浏览器验证集中放在三个原型主体完成后的最后阶段，继续属于 core。缺少 Windows 环境时，本运行可以停在安全的 `awaiting_next_phase`，但不得生成最终 `change-0.md`、有效需求快照或宣告整个工作流完成。

## 5. 功能需求

- `FR-001`：现有 Web 应用必须提供一个隔离的 Task UI 原型入口；该入口必须使用确定性内存夹具，并且不得要求登录、PostgreSQL、Task API 或外部网络服务。
- `FR-002`：原型入口不得改变现有账号、会话、设备配对和设备撤销入口的可观察行为；正常 Web 入口不得被 Task UI 原型取代。
- `FR-003`：夹具必须从固定 seed 和声明的 profile 确定性生成稳定且唯一的 Task Key、父子关系、同级依赖、标题、正文、Owner、Owner 继承来源、逻辑角色、状态、UTC 截止时间、标签、展示类型和子任务统计。
- `FR-004`：夹具必须完整支持 `deep-tree`、`wide-siblings` 和 `dense-dag`：分别覆盖 8 层导航、一个父级下 200 个直接子任务，以及 36 节点较密集无环依赖。
- `FR-005`：原型有效状态必须按产品语义表达为未开始、进行中、已阻塞和已完成；已阻塞可以由基础状态结合人工或依赖阻塞派生，归档不得混入本次活动 DAG 状态。
- `FR-006`：原型任一时刻必须只渲染一幅 DAG。该 DAG 的作用域必须是虚拟项目根或一个普通任务，其节点必须恰好是该作用域的直接子任务。
- `FR-007`：DAG 必须展示当前作用域内全部可见节点，包括没有依赖边的孤立节点；依赖边必须明确表达 predecessor → successor 方向，不得绘制跨父级边、自环或环。
- `FR-008`：DAG 必须位于尺寸有限、可滚动的视口内；允许虚拟化、视口裁剪和聚焦，但不得使用无限画布、语义缩放、递归子图或同时显示第二幅 DAG。
- `FR-009`：项目顶级 DAG 和每个新进入的子任务 DAG 初始都不得自动选择任务；没有选择时右侧详情抽屉必须收起，页面只显示当前 DAG 及其导航、搜索和筛选控制。
- `FR-010`：用户选择一个 DAG 节点后，系统必须选中该任务并从右侧打开非模态详情抽屉；抽屉打开期间选择另一个 DAG 节点必须直接替换抽屉内容，且不得触发 DAG 重新布局或改变当前父级作用域。
- `FR-011`：详情抽屉必须展示 Task Key、标题、正文、显式 Owner、有效 Owner、继承来源、逻辑角色、有效状态、本地化截止时间、标签、展示类型和直接子任务统计。
- `FR-012`：详情抽屉必须以列表形式展示当前选中任务的直接子任务摘要；该列表不得渲染依赖图，点击列表行不得进入下一层，也不得替代左侧 DAG 的选择语义。
- `FR-013`：详情抽屉必须在右上角提供明确的收回按钮，并支持 `Escape` 收回。收回后必须清除任务选择和选中高亮，仅保留 DAG；当前层级、搜索、筛选、DAG 视口和滚动位置不得改变，键盘焦点必须返回刚才的 DAG 节点。
- `FR-014`：详情抽屉必须为有直接子任务的当前任务提供唯一的“进入子任务视图”按钮；没有直接子任务时该按钮必须禁用并说明原因。
- `FR-015`：点击“进入子任务视图”后，当前父级作用域必须变为刚才选中的任务，左侧 DAG 必须整体替换为该任务的直接子任务及其同级依赖；抽屉必须收起、选择必须清空，并且不得自动选择第一个子任务。
- `FR-016`：面包屑必须表达从虚拟项目根到当前父级作用域的祖先链；“返回上一级”必须恢复上一父级作用域的 DAG、筛选状态、搜索状态、视口和滚动位置，同时保持没有选择且抽屉收起。
- `FR-017`：项目级搜索必须支持 Task Key 精确或前缀匹配，以及标题不区分大小写的包含匹配；选择搜索结果必须恢复其祖先链和父级 DAG，选中目标节点并打开详情抽屉。
- `FR-018`：搜索导航前必须保存当前页面位置；“返回搜索前位置”必须恢复搜索前的父级作用域、DAG 视口、滚动、筛选、选择和抽屉状态。
- `FR-019`：有效 Owner、逻辑角色、有效状态、截止时间和标签筛选必须只作用于当前 DAG，多条件按 AND 组合；过滤依赖边时只显示两端都可见的边，并明确提示存在与隐藏节点相关的依赖。
- `FR-020`：筛选导致当前选中节点不可见时，系统必须清除选择并收起抽屉，不得继续展示与可见 DAG 不一致的任务详情。
- `FR-021`：普通、冲刺和里程碑必须使用图标、边框、文字标记或等价的非纯色差异外观，但三者必须复用相同的节点选择、抽屉、搜索、筛选、依赖和层级导航行为。
- `FR-022`：DAG 节点、搜索、筛选、面包屑、返回按钮、抽屉控制和“进入子任务视图”必须可通过键盘到达和操作；焦点必须可见，任务状态、依赖方向和展示类型不得只用颜色表达。
- `FR-023`：原型刷新后可以确定性回到项目根 DAG、无选择和抽屉收起状态；本原型不得依赖持久化选中状态、URL 深链或浏览器历史才能恢复可用状态。
- `FR-024`：夹具或派生数据存在重复 Key、缺失父任务、跨父级依赖、自环或环时，原型必须稳定拒绝该数据并显示可诊断错误，不得渲染一幅可能误导用户的部分 DAG。
- `FR-025`：空 DAG、无搜索结果、无筛选结果和无直接子任务必须显示明确空状态；用户必须能清除搜索或筛选并恢复原始确定性数据。
- `FR-026`：原型不得读取或发送真实项目内容，不得调用外部 API、AI 或 LLM，也不得通过客户端夹具改变服务端 Task、Workspace 或身份数据。
- `FR-027`：macOS 主体验证必须覆盖三个 profile、深层往返、200 节点滚动与交互、搜索恢复、筛选、依赖方向、抽屉、键盘和非颜色状态，并在 `prototypes/task-ui/results/` 产生可追溯记录。
- `FR-028`：三个原型主体完成后，必须在 Windows 11 x64 真实浏览器重复 Task UI 的 core 兼容场景；该验证未通过前，本工作流不得最终封存。

## 6. 用户流程或调用流程

### 6.1 打开项目根 DAG

1. 用户从隔离的原型入口打开 Task UI，不需要登录或启动数据库。
2. 系统加载选定的确定性 profile，校验任务树与各父级 DAG。
3. 系统以虚拟项目根作为当前父级作用域，在左侧有限视口显示全部顶层任务及其同级依赖。
4. 初始没有选中任务，右侧抽屉收起，用户只看到 DAG 与导航、搜索、筛选控制。

### 6.2 查看任务详情

1. 用户通过指针或键盘选择当前 DAG 中的任务节点。
2. 系统保持当前父级作用域和 DAG 布局不变，从右侧打开详情抽屉。
3. 抽屉展示完整任务字段和直接子任务列表。
4. 用户选择另一个 DAG 节点时，抽屉原位替换为新任务内容。
5. 用户点击抽屉右上角收回按钮或按 `Escape` 后，抽屉收起、选择清空，焦点回到刚才的节点。

### 6.3 进入和返回子任务视图

1. 用户先在 DAG 中选择一个有直接子任务的任务。
2. 用户在抽屉中点击“进入子任务视图”；点击直接子任务列表行不会执行该动作。
3. 系统把选中任务设为新的父级作用域，以它的直接子任务整体替换左侧 DAG。
4. 系统清空选择并收起抽屉，不自动选择任何子任务。
5. 用户可以重复选择节点并通过专用按钮逐层下降。
6. 用户点击“返回上一级”或面包屑祖先后，系统恢复对应父级 DAG 及已保存的筛选和视口位置，保持无选择且抽屉收起。

### 6.4 搜索定位和恢复

1. 用户输入 Task Key 或标题。
2. 系统在当前项目的确定性任务集合中返回匹配项，并保留搜索前完整页面位置。
3. 用户选择结果后，系统恢复目标祖先链，显示目标所在父级 DAG，选中目标节点并打开详情抽屉。
4. 用户执行“返回搜索前位置”后，系统恢复搜索前的父级作用域、DAG 视口、筛选、选择和抽屉状态。

### 6.5 筛选当前 DAG

1. 用户设置一个或多个 Owner、角色、状态、截止时间或标签条件。
2. 系统按 AND 组合过滤当前 DAG 节点。
3. 系统只绘制两端均可见的依赖边，并提示存在被过滤端点时的隐藏关联。
4. 如果选中节点被过滤，系统清除选择并收起抽屉。
5. 用户清除筛选后，系统恢复该父级作用域的完整确定性 DAG。

### 6.6 原型验证

1. 验证者在当前 macOS Apple Silicon 的真实 Chromium 浏览器中记录 commit、浏览器、分辨率、缩放、硬件和 profile。
2. 验证者执行深树、宽层级和密集 DAG 的规定路径，并记录功能、键盘、非颜色状态和性能结果。
3. 主体 core 结果通过后，记录可以标记为 `pass`，并允许继续 Agent Context 主体工作。
4. 三个原型主体完成后，在 Windows 11 x64 真实浏览器执行最终兼容场景；Task UI 工作流只有在该 core 结果通过后才能最终封存。

## 7. 数据、接口与状态

### 7.1 原型任务数据

每个原型任务至少包含：

- 稳定内部 ID 和稳定 `Task Key`。
- `parentTaskId` 或等价父引用；空值表示虚拟项目根下的顶层任务。
- 标题和统一正文。
- 可空显式 Owner、解析后的有效 Owner，以及 Owner 继承来源任务。
- 可选逻辑角色。
- 基础状态、人工或依赖阻塞信息，以及派生有效状态。
- 可选 UTC 截止时间；显示时使用设备系统时区。
- 标签集合。
- `normal / sprint / milestone` 展示类型。
- 直接子任务数量和状态统计。

### 7.2 依赖数据

- 每条依赖包含 predecessor Task ID 和 successor Task ID。
- 两端必须属于同一 project 和同一父级作用域。
- 两端不得相同；同一方向边不得重复。
- 每个父级作用域必须独立校验无环。
- 过滤只改变可见投影，不改变原始依赖事实。

### 7.3 确定性 profile

- `deep-tree`：深度 8，逐层按规范生成子任务，依赖密度为 sparse。
- `wide-siblings`：包含一个具有 200 个直接子任务的父级，依赖密度为 medium。
- `dense-dag`：当前层 36 个节点，依赖密度为 dense-acyclic。
- 所有 profile 使用 seed `20260724` 和 Project Key `ZERO`；相同版本输入必须生成相同 Key、关系、展示字段和依赖。

### 7.4 客户端交互状态

原型至少维护以下非持久状态：

- 当前 profile。
- 当前父级作用域；空任务 ID 表示虚拟项目根。
- 当前 DAG 的可见节点与边。
- 当前选中任务；空值表示抽屉收起。
- 抽屉开关；必须与选中任务状态一致。
- 当前搜索条件、结果和搜索前位置快照。
- 当前筛选条件。
- 每一层需要恢复的 DAG 视口、滚动和筛选状态。
- 面包屑祖先链。

刷新可以清空这些状态并回到确定性项目根。原型不新增数据库表、migration、服务端持久化或公共 Task API。

### 7.5 接口边界

- 原型数据生成、树/DAG 派生和校验应保持可由自动化直接调用，不把关键规则只写在 React 组件中。
- Web 只消费本地夹具接口；不得把客户端派生结果作为正式服务端契约。
- 生产账号、配对和 Workspace API 保持现有接口与授权行为。
- 精确组件拆分、布局算法和新增依赖由后续规划在不违反本需求的前提下决定。

## 8. 异常、边界与恢复

- 重复 Task Key、孤儿父引用、跨项目或跨父级依赖、自环、重复边和依赖环必须在展示前被拒绝，并提供稳定、可定位的数据错误。
- 当前父级没有直接子任务时必须显示空 DAG 状态；不得保留上一层 DAG 或抽屉内容。
- 当前任务没有直接子任务时，“进入子任务视图”必须禁用并说明原因。
- 搜索或筛选没有结果时必须显示空结果和清除入口，不得改变原始夹具。
- 筛选隐藏选中节点时必须清除选择和抽屉，防止详情与可见 DAG 不一致。
- 关闭抽屉、进入子任务视图和返回上一级必须保留规定的层级、过滤和视口状态，不得残留来自其他作用域的节点或边。
- 截止时间无效时必须作为夹具错误处理，不得按本地时间猜测或修正权威值。
- 200 节点或密集 DAG 无法满足 core 交互与方向正确性时，主体结果必须为 `fail`；证据不足时必须为 `inconclusive`，不得标记 `pass`。
- macOS 主体完成而 Windows 环境仍不可用时，保存完整主体结果并安全等待最终兼容阶段；不得把 Windows core 改为 supplemental。
- 本功能不涉及持久化数据迁移、不可逆数据变更或多写并发，因此数据回滚和并发恢复不适用。实现恢复以移除隔离原型入口及其夹具/样式改动、恢复现有 Web 行为为边界，不得删除用户拥有的无关改动。

## 9. 非功能需求

### 9.1 性能

- 在当前 macOS Apple Silicon、真实 Chromium、至少 1280×720、100% 缩放的主体环境中，夹具加载后的节点选择、搜索、筛选和层级切换主要界面更新 P95 必须不超过 200 ms。
- `wide-siblings` 的 200 节点连续滚动期间必须保持输入可响应，不得出现持续阻断操作、错误选择、空白视口或节点与依赖错位；测量方式和结果必须记录。
- 暖缓存环境下原型首次可交互必须小于 3 s。
- 性能优化不得通过隐藏应展示的节点、丢弃有效依赖、改变筛选语义或只测量空数据来达标。

### 9.2 可访问性与视觉

- 主体界面使用中文。
- 所有主要操作必须可通过键盘完成，焦点必须可见；打开或关闭抽屉后焦点顺序必须稳定。
- 状态、展示类型、选中、阻塞和依赖方向不得只通过颜色传达。
- 详情抽屉必须是非模态的；打开时 DAG 不得重新布局，用户仍可直接选择其他 DAG 节点。
- 桌面主体视口至少为 1280×720、100% 缩放；移动端和更小视口不属于 core。

### 9.3 兼容性与安全

- 当前主体环境为 macOS Apple Silicon 的真实 Chromium。
- Windows 11 x64 真实浏览器兼容验证在三个原型主体完成后集中执行，并继续作为 core。
- Safari、Firefox 和其他桌面浏览器属于可选补充验证。
- 原型不得要求外部网络服务，不得发送真实业务内容，不得放宽现有认证、Cookie、设备或 Workspace 授权边界。

### 9.4 构建与可维护性

- 原型必须保持仓库现有 Web 和共享包可构建、可类型检查。
- 确定性数据、树/DAG 校验和关键状态转换必须能够脱离视觉截图进行验证。
- 正式业务规则不得只存在于 CSS、组件显示文本或人工测试步骤中。
- 不要求为本原型建立服务端缓存、SSR、独立微应用或生产级监控。

### 9.5 结果与运维

- 每次真实原型执行必须新增符合 `prototypes/task-ui/results/README.md` 约定的结果记录，不覆盖历史结果。
- 结果必须明确为 `pass`、`fail` 或 `inconclusive`，并包含环境、路径、测量、观察问题和证据位置。
- 若原型结论要求改变 ADR-008、H-005 或产品 Task UI 基线，必须另行提出文档变更，不得只在实现中静默偏离。

## 10. 初步实现方向与影响范围

- 在 `apps/web` 中保留现有账号/配对应用行为，并增加可重复进入的隔离 Task UI 原型界面。
- 在 `packages/test-fixtures` 或等价共享测试区域扩展确定性任务生成、父子索引、有效 Owner 派生、局部 DAG 生成和校验；不得依赖浏览器组件才能生成数据。
- 将 Web 原型按当前作用域 DAG、导航/搜索/筛选、详情抽屉和直接子任务列表拆分为可独立验证的职责。
- DAG 使用有限滚动视口、稳定布局和必要的渲染裁剪；具体布局算法或第三方依赖由规划阶段基于 36 节点密集图和 200 节点宽层级风险选择。
- 抽屉使用右侧非模态覆盖方式，避免打开详情时重新计算或移动 DAG；抽屉开关与选择状态保持单一事实来源。
- 搜索定位和层级返回使用显式状态快照，避免从显示文本猜测祖先链或恢复位置。
- 自动化优先覆盖确定性生成、无环/同级约束、状态转换、搜索/筛选和抽屉/层级不变量；真实浏览器证据覆盖布局、键盘、焦点和性能。
- 预计影响范围限于 Web 原型、共享测试夹具、相关测试、Task UI 结果证据及本功能工作流文档；不应修改 API、数据库、Object Store、Workspace CLI 或生产 Task 写入契约。
- 主要风险是 200 节点 DAG 的布局与滚动性能、密集边可读性、过滤后依赖含义、抽屉与选择状态漂移，以及夹具状态名称与最小生产契约混用。
- 所有后续实现阶段必须保持以下不变量：任一时刻只有一幅当前作用域 DAG；依赖不跨父级；未选择时抽屉收起；下降层级只能通过专用按钮；进入新层后选择清空且抽屉收起；现有 Web 认证/配对行为不回归；macOS 主体先完成，Windows core 最后集中验证。
