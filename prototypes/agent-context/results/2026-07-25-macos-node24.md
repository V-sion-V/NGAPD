## 结论摘要

无头 runner 的 12 个 core 场景全部通过。正常预算下必需来源需要 `3050` tokens，最终选用 `5810`，剩余 `190`；低于 `3050` 时稳定返回 `INSUFFICIENT_CONTEXT_BUDGET`，不产生部分 manifest 或任务分析。

manifest 共包含 28 个可诊断条目并与正文分离。所有分页组合逐项等于未分页结果；预算、输入版本、页大小或排序事实变化后旧游标稳定失效。渐进读取只接受已选的精确版本引用，并在每次读取重新检查 actor、明确意图和底层读取事实。

工具授权在加入提示注入和恶意角色文本前后逐字段保持：

```json
{
  "readScope": "selected_sources",
  "writeScope": "none",
  "adminMode": false,
  "lease": false,
  "requiresConfirmation": true
}
```

原型只使用内存合成值和仓库内合成夹具；没有登录、数据库、Web、真实 Workspace、生产授权修改、外部网络、API、AI、LLM、Skill 执行、管理员模式或写租约。

## 来源、摘要与结构化分析

- 冲突顺序固定为系统 > 项目 > 当前任务 > 用户流程；`context-sources.json` 不再把任务置于项目规则之前。
- 活动祖先按近到远排序；已完成 predecessor 的确认摘要进入默认候选；未完成 predecessor 排除。
- 当前任务直接关注只展开一跳，重复 Task ID 去重，环和长链不递归。
- 已确认摘要覆盖 `agent_provided`、`user_provided`、`system_fallback`，并保留来源任务、工作周期和版本；未确认摘要排除。
- 项目与当前用户启用的 Skill 只提供稳定入口；项目级同名 Skill 优先；发现和读取不改变工具能力。
- 参考消费者仅使用成功读取结果，稳定输出任务目标、约束、角色边界、祖先、predecessor、一跳关注、权限限制和排除项。移除任一必需读取后状态为 `incomplete / required_source_missing`。
